## Highlights

- **SOCKS5 proxies.** A profile endpoint can now use the SOCKS5 transport, next to HTTP and HTTPS.
  Host names are always resolved by the proxy, so DNS lookups do not leave through your local
  resolver. HTTP, HTTPS, WebSocket and downloads all route through it.
- **SOCKS5 authentication in Firefox.** Firefox sends the SOCKS5 username and password.
  Chromium-based browsers (Chrome, Edge, Yandex Browser) have no extension API for it: the
  credentials stay saved, the profile shows **Authentication unsupported in this browser**, and
  requests through a proxy that requires a login fail instead of going direct.
- Proxy text import and paste accept `socks5://` and `socks5h://`; profiles copy as `socks5h://`
  URLs and curl commands. SOCKS4 remains unsupported.

## Fail-closed routing

- An unreachable SOCKS5 proxy or a rejected login never falls back to a direct connection.
- Fixed: native JSON import accepted any proxy host text, and the profile editor stored hosts with
  surrounding spaces. Such a value could make Chromium discard the proxy rule and connect
  directly. Unsafe hosts are now rejected on import, trimmed on save, and an already stored unsafe
  profile is not applied (it shows a profile error instead).

## Data

Configuration schema moves from v5 to v6 (new `SOCKS5` transport value). Existing settings and
native exports are migrated automatically; older ProxyLoom versions will not load a v6
configuration.

## Known limitations

- SOCKS5 login works only in Firefox; see [Known limitations](../user-guide/known-limitations.md)
  and ADR-016.
- Firefox reports a rejected SOCKS5 login like a refused connection, so ProxyLoom cannot say that
  the password is wrong.
- FoxyProxy import still skips SOCKS entries (planned).

## Privacy

No new permissions, network requests or data collection. No telemetry.
